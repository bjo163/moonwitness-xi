# Maintenance runbook

This runbook is the handoff point for routine maintenance. Scheduled workflows use the default branch on GitHub; a workflow present on `dev` is not proof that its schedule is active. Before treating any scheduled row as operational, confirm its workflow exists on `main`, the Actions schedule is enabled, and its first run completes against the recorded source SHA. Protected promotion and required review remain mandatory.

## Failure handling and handoff

1. Record workflow name, run URL, source SHA, failed job/step, impact, and whether the workflow wrote any external state. Use sanitized output only; do not copy credentials, user data, or raw secret-bearing artifacts into issues.
2. The accountable role reproduces locally when possible and creates or updates the matching roadmap evidence. Keep security, failed required checks, stale-SHA, permission and unknown external-state conditions open until their acceptance evidence exists.
3. For a remote write with an ambiguous response, read remote state first and retry only when the idempotency contract proves the write did not land. Stop when permission is missing or state is conflicting; escalate to the repository administrator rather than expanding token scope.
4. For a protected promotion or publication blocker, provide the CODEOWNER/repository administrator the exact PR, source SHA, passing technical checks, failed gate and requested action. Do not merge, deploy or alter rulesets on their behalf.
5. After recovery, rerun the failed acceptance on the same source when possible; if code changes, record the new SHA and repeat all checks affected by that change. Update `ROADMAP.md`, the task evidence and linked issue through the authorized workflow, then commit and push the evidence to `dev`.

## Current ownership and known limits

Owners are roles until repository maintainers assign named people. The maintainer on duty owns triage routing; CODEOWNER/repository administrators own protected review and settings; API/database, Board, docs, security, platform and release maintainers own their corresponding lanes. No individual on-call rotation or response-time SLA is configured by this repository.

At this handoff, activation of schedules from `main`, fresh CODEOWNER approval for PR #24, trusted Pages publication, exact promoted-SHA release proof, private billing/registry visibility, and any real receiver credentials remain external. PostgreSQL tests require `POSTGRES_TEST_URL` locally; hosted required integration/restore CI is the execution source when local credentials are unavailable. The default CI runner remains Ubuntu 24.04 until a separate reviewed migration is made. Optional GitHub Projects projection and inbound GitHub App issue intake remain backlog items under their re-entry criteria in `docs/roadmap/ACTIVE-PLAN.md`.
