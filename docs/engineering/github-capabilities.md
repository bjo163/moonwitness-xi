## Read limits and recheck points

- Reads used public repository metadata, branch objects, ruleset list/details, workflow directory contents, and the PR endpoint. No secrets or environment values were requested or recorded.
- Public endpoint allowlist rejection is distinct from HTTP authorization denial and from a feature being disabled. Pages configuration, Actions permission settings, registry configuration, GitHub Projects v2, and exact classic branch-protection details remain unknown here.
- Before enabling a workflow, changing settings, publishing Pages, or publishing a release, re-read the exact ref, PR head, checks, rulesets, and the relevant capability endpoint with an authorized surface. The promotion PR is the mechanism for content changes; repository settings are not changed by this document.
