## Coverage

`apps/api/tests/auth.test.ts` exercises direct REST requests and JSON-RPC search/search_read against the same record scope. An ordinary user cannot fetch another company's partner by ID (404), update it, create a row under a foreign company, or select an unauthorized `X-Company-Id`. Count and list results remain scoped to the user's company; response payloads do not include the foreign tenant or its partner. Eager relation graphs that could cross the tenant boundary are rejected. Group grants are needed for write/create and do not bypass company scope.

The JSON-RPC surface maps only `search`, `search_read`, `create`, `write`, and `unlink`; it has no separate count/export operation. Board CSV export is client-side over the scoped list response, so the server list scope is the enforcement point.
