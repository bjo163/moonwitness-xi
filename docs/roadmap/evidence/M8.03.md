# Evidence M8.03 — Security scanning and vulnerability policy

## Status

- Status: implementation prepared; GitHub CodeQL analysis and repository-side alert visibility require hosted execution and token/settings access.
- Source SHA: record after commit and hosted execution.
- Scope: CodeQL JavaScript/TypeScript and Actions, locked workspace dependency vulnerability scan, critical severity gate, SARIF upload, and exception expiry validation.

## Delivered

- `.github/workflows/codeql.yml` runs on PR/push to `dev` and `main`, weekly, and manually. Only the analysis job receives `security-events:write`.
- The `containers` CI lane scans the root pnpm lockfile for CRITICAL dependency advisories, fails closed on actionable CRITICAL findings, and uploads SARIF when produced. This is a workspace dependency scan, not a claim of container-layer scanning.
- `docs/security/vulnerability-policy.json` defines the severity policy and starts with no suppressions. Any future exception must have an ID, owner, reason, and ISO expiry date; expired or malformed exceptions fail CI.
- Unit tests cover detection of a seeded CRITICAL result, scanner errors, and expired/incomplete exceptions.
- GitHub repository API on 2026-10-05 reported secret scanning and push protection enabled, Dependabot security updates disabled, and non-provider-pattern secret scanning disabled. Reading code-scanning alerts was unavailable to the current CLI token (`404 no analysis found`, `admin:repo_hook` scope required); no alert coverage is claimed from that response.

## Limitations

- Trivy scans dependencies from the workspace lockfile and does not scan the built OCI image layers. Image-layer scanning remains separate follow-up work if the CI scanner configuration is expanded.
- Scanner output may reveal genuine advisories; they must be triaged and remediated or narrowly excepted with expiry, never hidden by broad ignores.
- This evidence does not assert that CodeQL has completed or that the repository has zero findings.
