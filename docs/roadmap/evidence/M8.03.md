## Verification

### Vulnerability exception expiry validation hardening

- Review found that expiry validation checked only the `YYYY-MM-DD` string shape; impossible dates such as `2026-99-99` passed the active-date comparison and could leave an invalid suppression in the policy file.
- `scripts/security-scan-policy.mjs` now validates a real Gregorian calendar date, including leap-year rules, requires a real array of exception objects with non-empty string identity/owner/reason, and rejects malformed entries instead of throwing or accepting them.
- Regression cases cover out-of-range month/day, non-leap February 29, valid leap-day expiry, null entries, and non-array policy data.
- `pnpm test:security-policy` — pass, 11/11; `node scripts/check-vulnerability-policy.mjs` — pass, 0 active exceptions; targeted ESLint, Prettier and `git diff --check` — pass.

### Scoped exception enforcement

- The SARIF gate now labels every result with its scan target and loads the checked-in vulnerability policy. It requires all three reports, validates policy severity and exception metadata, then suppresses only a finding whose exact SARIF rule ID and target both match a current exception.
- Exceptions are unique per target/rule-ID pair; an exception for an API image cannot permit the same finding in the workspace lockfile or Board image.
- CRITICAL workflow annotations now include a sanitized target/rule-ID pair, so the owner can tell whether a finding came from the workspace, API image or Board image.
- Tests cover exact target/rule scoping, duplicate and unknown targets, unsafe IDs, and fail-closed missing scan reports. The checked-in exception set remains empty; CRITICAL findings continue to block by default.
- `pnpm test:security-policy` — pass, 14/14; `node scripts/check-vulnerability-policy.mjs` — pass, 0 active exceptions; targeted ESLint, Prettier and `git diff --check` — pass.
