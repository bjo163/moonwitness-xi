## Implemented

- `scripts/roadmap/lifecycle.mjs` keeps work status separate from delivery stage. It rejects completion without acceptance evidence and a full source SHA, reports incomplete declared dependencies as blockers, and validates supplied ancestry/check/release facts. A completed task with an incomplete hard dependency remains complete for its work evidence but is blocked from issue close; this avoids rejecting the whole snapshot while preserving the dependency blocker.
- `verified-dev` requires the task source to be in the dev history and every supplied required check to have completed successfully on the exact current dev head SHA. A green check for an older SHA does not qualify.
- `in-main` and `released` remain distinct. A release needs valid version metadata, main ancestry, and an explicit fact that the release manifest contains the task source.
- Closing an issue is only proposed when acceptance is complete, no hard dependency is incomplete, and delivery has reached verified-dev or later. A manually closed incomplete task is reported as `needsTriage`; it is never reopened automatically.
- `scripts/roadmap/sync-issues.mjs` accepts an optional lifecycle projection, includes it in the stale-plan fingerprint, and renders lifecycle facts into the managed issue body. Without a projection, existing planner behavior remains unchanged.
- `scripts/roadmap/lifecycle-snapshot.mjs` accepts an ephemeral, versioned snapshot only when repository ID and plan SHA match and its timestamp is at most five minutes old. It requires unique known records for every indexed task, resolves hard dependencies from the full snapshot, reads current issue state by the stable repository/task marker, and rejects duplicate issue identities. The CLI imports this only in plan mode and refuses `--apply` when a lifecycle snapshot is supplied.
- `scripts/roadmap/collect-lifecycle-snapshot-cli.mjs` validates the checkout and task index, reads paginated `ci-gate` check runs for exact `origin/dev` SHA and non-draft releases with `gh api`, and verifies task/release ancestry using local full Git history. These endpoints are public read-only; repository/token identity is still validated by the API data and workflow context. It parses explicit full source SHA evidence only; checked tasks without an attributable implementation SHA remain complete work but are excluded from delivery verification/close candidates.
- `Roadmap issue sync` now grants `checks: read` to its plan job, fetches full history, creates an ephemeral lifecycle snapshot, and prints lifecycle/close-candidate counts in its body-free plan summary. The snapshot is removed with an EXIT trap. Apply still uses its separate, opt-in `issues: write` job; lifecycle-driven issue closing is not enabled.
