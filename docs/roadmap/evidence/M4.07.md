## Contract

- REST page size is limited to 1–500; offset and cursor must be non-negative safe integers and cannot be combined. Cursor mode accepts ascending ID order only.
- REST domain terms and selected fields are each limited to 100. `order` and relation expressions are limited to 512 characters.
- Eager relation paths may contain at most three segments. Normal one- and two-level graphs remain supported, including comma-separated top-level relations.
- JSON-RPC `search_read` enforces the relation-depth, selected-field-count, and sort-length bounds. Its domain is limited to 100 top-level terms.
- Fastify rejects request bodies larger than 1 MiB before route processing.
- Writes continue to use generated model schemas; unrecognized properties fail validation and do not create a row.

## Limitations

- The domain bound counts top-level terms; deeply nested JSON is also bounded by the 1 MiB body/request-target handling and is validated by the ORM parser. The API does not expose an arbitrary SQL fragment interface.
- The body cap is an application-wide Fastify setting. If future uploads require larger payloads, they need a separately bounded route/parser instead of raising the global limit.
- Hosted CI status is recorded after push; no claim of CODEOWNER promotion or merge is made by this evidence.
