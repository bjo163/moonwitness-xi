## Threat cases and outcomes

- Password storage/verification uses salted scrypt; password values/hashes stay out of JSON, audit payloads and database errors.
- Unknown login and wrong password produce the same 401 response; IP-based login/register and refresh throttles are configured.
- Refresh values are opaque; only SHA-256 hashes persist. Rotation, same-token concurrency and replay-family invalidation have unit and PostgreSQL tests.
- Password change verifies current credentials, updates the hash and revokes all refresh sessions. Protected requests read current role, user active state and partner active state from the database.
- Existing access JWTs are stateless. Role demotion takes effect immediately because role is read from DB; user/partner deactivation makes old tokens fail immediately. Password change alone cannot revoke an already issued access JWT; with the default 900-second `ACCESS_TOKEN_TTL_SECONDS`, the maximum remaining exposure is bounded by the token's remaining lifetime.
