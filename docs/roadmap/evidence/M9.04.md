## Production transport HTTPS regression — 2026-10-07

- The earlier local TLS receiver used a custom `https.request` inside the injected `send` adapter, so it did not exercise the production sender. The sender now lives in internal `src/transport.ts`; the TLS fixture calls that implementation with a test-only port/CA and a loopback address while production still validates public DNS before choosing the pinned address.
- The exact production request code is exercised for TLS chain and hostname validation against `receiver.example`, pinned address lookup, signed body and headers, 503 retry followed by 204 success, and an absolute request deadline while a receiver streams bytes every 25 ms. The timeout fixture uses a short internal test duration; production deadline remains 10 seconds in addition to the socket inactivity timeout.
- Running the previously bypassed sender exposed a Node lookup callback incompatibility: when `lookupOptions.all` is true, Node expects an array of `{address,family}` records. The old callback returned the single-result tuple and failed with `ERR_INVALID_IP_ADDRESS` before connecting. The production lookup callback now handles both `all: true` and single-result signatures.
