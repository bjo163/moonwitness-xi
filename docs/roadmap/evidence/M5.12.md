## Delivered

- Added direct `@moonwitness/ui/components/chart` exports for typed `BarChart` and `LineChart`; SVG rendering adds no chart runtime dependency.
- Bar chart is horizontal and compact for categorical dashboard status; long visible category labels truncate safely while exact labels and values remain in SVG titles and the semantic table. A muted track keeps valid zero values visible without inventing nonzero data.
- Line chart accepts explicit labels and multiple typed series. It skips missing/non-finite points, provides per-point SVG titles and a series legend, and includes a tabular alternative.
- Both charts distinguish loading, error, and empty states from valid zero-valued observations. Values use `Intl.NumberFormat` with a caller-supplied locale or a consumer formatter; date/time label locale and timezone remain caller-owned and explicit.
- Added shared chart colors using `--mw-chart-*` tokens; meaning must not rely on color alone. Scoped CSS handles narrow viewports with contained horizontal overflow.
- Integrated a live `Background job status distribution` chart in the admin dashboard from the existing jobs health snapshot: queued, running, dead, outbox pending, and outbox dead. It does not label this single live snapshot as historical trend data.
- Extended dashboard browser coverage for chart visibility, semantic table, mobile viewport overflow, and responsive light/dark visual audit; audit waits for the chart rather than capturing a network-race loading frame.

## Reuse decision

Keep chart primitives in `@moonwitness/ui` for now. The repository has one real chart consumer and the implementations are small, dependency-free SVG components using existing token infrastructure. A separate `@moonwitness/charts` package would currently add package/build/version overhead without actual reuse. Revisit extraction when a second independent app needs shared chart behavior or the chart layer gains a distinct dependency/maintenance boundary.

## Handoff

- Do not create synthetic history from polling snapshots; add a time-series chart only after a durable history API has explicit retention and aggregation semantics.
- Callers must provide locale/timezone decisions; do not infer timezone from a locale or numeric language ID.
- Preserve the table alternative when extending chart interactions; a hover-only tooltip is not sufficient access to values.
