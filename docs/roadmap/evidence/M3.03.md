## Coverage and findings

- Invalid credentials and successful superadmin login remain covered by the existing auth E2E suite.
- Reload restores an authenticated session.
- An expired but correctly signed access token triggers exactly one refresh for concurrent requests, rotates the refresh token, and preserves the authenticated page.
- Logout clears the persisted browser session, revokes the rotated refresh token, and subsequent protected-route navigation returns to login.
- An inactive account created through the authenticated API cannot establish a session; the API returns the same generic invalid-credentials response as for an unknown account.
- A protected deep link returns to its internal path after login. A tampered external return target is rejected and falls back to the Board root.
- The return target is now constrained to a same-origin absolute path before navigation. Protected routes preserve path, query, and fragment during login redirection.
