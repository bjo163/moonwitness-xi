## Result so far

- Added a pure access decision that denies missing/invalid classification, absent or withdrawn consent, tenant mismatch, unapproved purpose, and restricted access without an explicit server-derived grant.
- Denies child-sensitive records for general search, export, public projection, analytics, and model input. A public projection requires minimization, source/projection revision digests, and a reviewer distinct from the requester.
- Added retention decisions that deny missing or malformed owner-approved expiry and deny use after expiration; no retention duration is invented.
- Added a sanitized revocation plan containing only hashes of subject, consent-decision, and derivative references, plus a helper to exclude revoked records from a derived list.
- Added synthetic tests for access denial, tenant boundaries, child-sensitive restrictions, reviewer separation, retention, revocation filtering, and absence of plaintext canaries from emitted derived results.
- Added ORM-programmatic append-only revocation records and a privacy-steward access group, explicitly assigned only to the seeded superadmin. Generic model access to revocation and projection records is denied.
- Added a seeded synthetic restricted search projection and an explicit `synthetic` marker. The package service only reads and invalidates active synthetic projections, requires a matching active synthetic projection before recording a new withdrawal, accepts SHA-256 references only, commits the append-only event and invalidation in one transaction, supports exact idempotent replay under concurrent requests, rejects key conflicts, and fails closed if projection JSON or its digest is invalid. Non-synthetic projections are excluded from the API and untouched by this sample revocation flow.
- Added authenticated `POST /api/research/privacy/revocations` and `GET /api/research/privacy/projections`. The server derives actor/company from `request.auth`, generates the event timestamp server-side, requires the seeded superadmin privacy-steward group and active company membership, rejects extra body fields, and returns only revocation results or active synthetic projections. Exact idempotent retries replay the original event and timestamp. The API surface is limited to synthetic fixtures and does not enable intake of real personal data.
- Added a route-level cross-tenant negative case using an existing but unassigned synthetic company context. Both projection reads and revocation writes return 403; the canary is not returned, no event is recorded, and the source projection remains active.
- Steward authorization now requires both the company membership and `knowledge_privacy_steward` access-group membership to remain active. Synthetic service, route, and PostgreSQL integration coverage confirms that deactivating either membership or group denies projection reads and revocation writes without exposing canaries, creating an event, or invalidating the projection.
