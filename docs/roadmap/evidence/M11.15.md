## Audit contract

- Reads all open and closed Issues, milestone metadata, and repository labels through the existing bounded, paginated GitHub REST adapter.
- Matches only exact numeric repository ID + Task ID markers. Pull requests and other repository markers are ignored. Duplicate, orphan, and malformed managed records remain visible; the audit never deletes, closes, reopens, relabels, or comments.
- Compares current generated-block source SHA, expected milestone and namespaced labels, and Card/Evidence references against the task index. It does not fetch arbitrary URLs or inspect/print maintainer notes, comments, bodies, or assignees.
- Reports orphan issue IDs with a `needs-triage` recommendation. A maintainer applies the label/reason/expiry after review; the auditor does not perform that write.
- Local read-only report can be emitted to stdout or a repository-local ignored JSON file. Workflow trap removes the ephemeral file on both success and failure.
- The workflow continues to report missing/duplicate/conflict counts without converting ordinary drift into an automatic mutation or hiding it as success. API/auth errors fail the audit job.
