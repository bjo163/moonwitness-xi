## Follow-up security acceptance

- Workflow definitions are returned to roles allowed to transition as well as roles allowed to start; each result includes `canStart`. This lets reviewer-only roles see eligible actions without exposing a start action they cannot perform.
- Instance listing now requires an exact resource model/ID pair. List, detail, start and action validate read access and row rules against the underlying resource; company-bound records are restricted to the active company even for privileged roles.
- Board dev proxy now forwards `/workflows` to the API. The request addon sample gives `user`/`system` start eligibility while `superadmin` can review but cannot start.
