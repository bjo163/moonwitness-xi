# Evidence K2-003 — dataset release manifest and rollback pointers

## Status

- Status: in progress. Immutable dataset release metadata and an integrity-checked active pointer with rollback are implemented. End-to-end snapshot rebuild/replay and source-artifact retention are not yet implemented.
- Date: 2026-10-16 (Asia/Jakarta).
- Tested base: `cdbc1f969a413d05b87083e1adc9bd587d40ded3` on `dev`; implementation changes are local and uncommitted during this verification.
- Dependencies: K2-001 deterministic ingestion, K1-007 version contract, and K0-006 no-legacy-import disposition.
- Data: synthetic snapshot hashes only; no corpus/private source bytes were used.

## Result

- Added immutable, content-addressed dataset release manifests binding dataset semantic version, independent ontology/corpus versions, canonical snapshot digest, creation time, and the previously active release.
- Added explicit activation that verifies the release-manifest digest and dataset identity before writing a same-directory temporary active pointer and replacing the pointer via rename.
- Rollback reactivates a previous immutable release without deleting or overwriting either release manifest. Creating a release does not activate it, so interruption between creation and activation leaves the active selection unchanged.
- Repeated identical release creation is idempotent; corrupted digest collisions, invalid versions/digests, and missing activation targets fail closed.
