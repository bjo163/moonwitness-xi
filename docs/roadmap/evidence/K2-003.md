# Evidence K2-003 — dataset release manifest and rollback pointers

## Status

- Status: in progress. Immutable dataset release metadata now binds to a verified on-disk snapshot, and activation validates its files before atomically switching the active pointer. End-to-end snapshot rebuild/replay and source-artifact retention are not yet implemented.
- Date: 2026-10-16 (Asia/Jakarta).
- Tested base: `484d2b522cb56d71a59d69394124fb8f6fe81b67` on `dev`; implementation changes in this evidence update are local and uncommitted during verification.
- Dependencies: K2-001 deterministic ingestion, K1-007 version contract, and K0-006 no-legacy-import disposition.
- Data: synthetic snapshot hashes only; no corpus/private source bytes were used.

## Result

- Added immutable, content-addressed dataset release manifests binding dataset semantic version, independent ontology/corpus versions, canonical snapshot digest, snapshot directory, creation time, and the previously active release.
- Release creation validates the snapshot manifest digest and verifies that every record, alias, and source-artifact JSON file hashes to the exact digest lists in that manifest. Ingestion now materializes the complete empty-or-populated snapshot directory contract and can create/activate a release directly from its just-validated snapshot.
- Added explicit activation that verifies the release-manifest digest, dataset identity, snapshot manifest, and snapshot files before writing a same-directory temporary active pointer and replacing the pointer via rename. The pointer includes the selected immutable snapshot path.
- Rollback reactivates a previous immutable release without deleting or overwriting either release manifest. Creating a release does not activate it, so interruption between creation and activation leaves the active selection unchanged.
- Repeated identical release creation is idempotent; corrupted digest collisions, invalid versions/digests, and missing activation targets fail closed.
