## Coverage and findings

- Added a browser regression using the actual Board list backed by isolated PostgreSQL. It creates 23 uniquely named partners (21 active, two archived) and verifies the default active filter, full count, page boundaries, search from page two, active/archived filters, and sorting from page two.
- The test confirms search and sort return to page one, and the visible row set and total match the fixture. The list uses its configured page size of 20.
- The same browser test calls the real authenticated `/api/base.user` route using `with=partner,language&count=true`; PostgreSQL returns HTTP 200, total 1 for the constrained fixture, one row, and the expected related partner and language property.
- The existing PostgreSQL API integration test also covers the default two active base users, `partner,language`, and a total of two. No API runtime modification was needed because the existing comma-separated graph normalization and separate count query passed against PostgreSQL.
- During test development, the fixture exposed existing records in the local test database and the Partner default active filter; the final assertions isolate records by a unique search prefix and explicitly account for active/archived state.
