## Limits

- Execution is at-least-once around process crashes. Fencing prevents stale database completion, not repeated external side effects; external handlers need idempotency keys or receiver deduplication.
- Cancellation is cooperative. A handler that ignores its signal can continue until it returns; expired/fenced ownership still prevents it from committing as the current run.
- DST fall-back coalescing is covered. Other cron expressions/timezones can be added as project schedules require; deployment-specific scheduler/worker processes remain an operational activation concern.
- Hosted CI for this task is recorded after push; no CODEOWNER promotion or merge is implied.
