## Contract and implementation

- `pnpm release:prepare` is read-only by default. It reports candidate version, exact source/baseline SHAs, files that would change, and a stable release-input fingerprint.
- It updates root and `@moonwitness/*` package versions, release changelog notes, and generated README/reference docs during the apply path. Unscoped packages are left untouched.
- Generated notes carry a bounded managed block and SHA-256 fingerprint derived from baseline, candidate version, and sorted releasable commit SHAs. A retry with the same source inputs is a no-op even if the current source head or wall-clock date changed.
- Changelog edits preserve maintainer text outside the managed block and fail closed on duplicate/ambiguous sections or missing managed markers.
- `.github/workflows/release-prepare.yml` is explicitly dispatched on `dev` with a full expected SHA. It rechecks event SHA and `origin/dev`, uses the shared repository-write coordinator, creates no remote release branch, and pushes only through `push-expected-ref.mjs` after verifying the expected target SHA.
- The workflow has no image publication, tag creation, GitHub Release, Pages, or application deployment steps. It creates one release-preparation commit only when generated changes exist.
