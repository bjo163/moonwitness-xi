## Measurement snapshot

The checked-in local reference run used Node v26.5.0 and PostgreSQL 16.15 with five measured samples after one warm-up. The fixture contained 120 partners, 240 addresses, and eight jobs per sample. Query counts were 1 for list, 1 for count, 2 for eager loading at both 12 and 120 rows, and 10 per completed job. Median local durations were 2.55 ms list, 1.16 ms count, 2.94 ms for 12 eager-loaded partners, 6.46 ms for 120, and 18.43 ms/job. The JSON snapshot contains variability, heap observations, and full EXPLAIN plans. PostgreSQL selected sequential scans for both reads on this small synthetic fixture; that is not evidence for speculative indexes at production scale. These timings are machine-specific observations, not service-level objectives.

## Safety and interpretation

- The integration test creates one generated schema inside the CI-only PostgreSQL test database and drops it with `CASCADE` in `afterAll`; it does not touch another database or schema.
- Fixture emails and job payloads are synthetic and contain no passwords, sessions, connection URLs, or production rows.
- Query counts are deterministic structural budgets. Latency and heap readings include shared-runner variance and must not be represented as production SLOs.
- `EXPLAIN ANALYZE` executes only the two measured read shapes against the disposable synthetic schema.
