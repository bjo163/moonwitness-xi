# Evidence M7.13 — Idempotent release image tag reconciliation

## Status

Partial. OCI publishing now reads existing version tags before writing. A retry reuses a tag only when its image ID, source SHA, release version, and registry digest match the verified candidate; conflicting content/provenance fails before tag or push. ## Recovery behavior

- An absent OCI manifest is the only pull failure treated as an uploadable missing tag. Authentication, network, and other registry failures stop publication before writes.
- A missing version tag is pushed once and its OCI digest is recorded for later stable-latest digest comparison.
- A present version tag is reused only if candidate and remote image IDs match, both OCI revision/version labels match the expected SHA/tag, and exactly one registry digest is available. No Docker tag/push occurs on this path.
- A conflicting tag fails closed; the workflow never overwrites it. An ambiguous push can be retried: if the prior push actually completed, the next run reads and verifies the existing image.
- Before any image write, the publish job checks the remote tag's peeled commit SHA against `GITHUB_SHA`, preventing promotion if the Git tag moved after verify.
- Existing GitHub Releases are reused only when the tag, published state, and prerelease classification match the requested release.
- A retry reconciles the reused release's `latest` designation and re-applies the same stable image digest, recovering failures after GitHub Release creation or between the API and Board aliases.
- Release assets are immutable by name: existing digest or size mismatch fails before any upload; missing files upload only while the GitHub Release is a draft.
- After each upload, the reconciler re-reads the paginated asset inventory and verifies exact digest and size. If the CLI response is lost after GitHub accepted the upload, the verified remote asset is recorded as recovered without a duplicate upload.
- If an upload reports failure and the asset is absent on re-read, reconciliation fails closed. Published releases with missing assets are not mutated.
