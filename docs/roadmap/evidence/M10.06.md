## Failure and retry cases

| Scenario                                                               | Required behavior                                                                        | Verification                                                                                       |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Sensitive path, breaking change, or policy change requires approval    | Add `approval-required`; if auto-merge is already enabled, explicitly disable it.        | Workflow trust contract requires sensitive-only branch and disable command.                        |
| Compatible low-risk change can auto-merge                              | Request merge only after required checks, with `--match-head-commit` bound to event SHA. | Workflow trust contract requires exact head argument.                                              |
| `dev` advanced after an older push event                               | Stale workflow run exits before updating/creating the promotion PR.                      | Workflow trust contract requires remote-head comparison and stale-event guard.                     |
| Approval predates a changed PR head                                    | Exact-head checker rejects approval attached to prior commit.                            | `promotion-approval.test.mjs` regression; production gate runs it against fetched PR review pages. |
| Any mandatory CI job fails, cancels, skips unexpectedly, or is missing | `ci-gate` rejects the run.                                                               | `ci-gate.test.mjs` negative cases for each result class.                                           |

## Follow-up — discard stale promotion events across all later steps

A source review found that a stale guard which ran `exit 0` ended only its shell step; GitHub Actions would still execute later steps and could reconcile an old promotion head. The workflow now sets the step output `stale=true` before exiting and every subsequent PR lookup/create, risk classification, report refresh, approval-label, and merge step requires the event not to be stale. The trust checker validates the output and each named step; mutation tests remove the guard and verify the contract fails.
