## Release tag ancestry and prerelease consistency — `36325d1` — 2026-10-15

- The collector previously used a resolved tag commit as the task's `releaseManifest.sourceSha`. Lifecycle validation correctly requires that field to equal the implementation commit, so ordinary releases whose tag commit is a descendant of the task commit could not be projected as `released`. The snapshot now records the task source SHA separately from the full resolved release tag commit SHA.
- A task is assigned a release only when its accepted source commit is present on `main` and is an ancestor of a real resolved tag commit. The collector checks candidate releases newest-first and can skip a newer release that does not contain the task, malformed/nonexistent tag commits, drafts, and GitHub prerelease flags that disagree with the tag's SemVer suffix. A published RC stays labeled with its `-rc` version.
