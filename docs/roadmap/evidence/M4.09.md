## Contract and decisions

- ORM addon installation and explicit upgrade hooks run inside one transaction. A failed upgrade must roll back created schema/data and leave installed version unchanged.
- Generated PostgreSQL foreign keys, unique constraints, and common active/relation indexes are created from model definitions. Referential and duplicate failures are mapped to safe HTTP errors; SQL details and submitted values are not returned.
- Generic write plus audit/outbox recording is transaction-scoped; existing rollback tests prove the business row is not committed when outbox recording fails.
- Audit timestamps use ISO-8601 UTC values from the ORM lifecycle hooks.
- Concurrent writes to the same record follow **last-commit-wins**. Current models have no optimistic version token, and stale-write conflicts are not detected. Clients requiring conflict detection must serialize writes; version-based conflict handling remains a future compatibility-sensitive change.

## Scope and limits

- Last-commit-wins is intentionally documented; this is not optimistic concurrency control and does not guarantee users see a stale-write warning.
- Timezone coverage verifies ISO UTC audit timestamps and persisted user timezone values. DST conversion for future business-local datetime fields requires a separate explicit field contract and tests.
- Hosted CI status is recorded after push; no CODEOWNER promotion or merge is implied.
