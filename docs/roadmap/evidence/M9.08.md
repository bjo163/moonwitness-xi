## Bundle measurement

- The current Board production build (`pnpm --filter @moonwitness/board build`) completed with Vite 8.3.2. The primary entry chunk is 431,998 bytes, the stylesheet is 74,209 bytes, and the HTML preloads two JavaScript chunks in addition to the entry. The route model chunk is lazy-loaded; do not describe its entire size as initial transfer.
- Added `build.manifest`, `apps/board/bundle-budget.json`, `pnpm board:budget`, and `pnpm test:board-budget`. The report follows Vite's static import graph for initial assets and each direct lazy route, deduplicates shared chunks, reports raw/gzip bytes, and checks both incremental route chunks and each route's initial-plus-reachable-route-specific-lazy JavaScript total. Traversal stops at the shared HTML entry so alternative sibling routes do not inflate a page's cost. Missing entries, invalid references and malformed budget data fail closed.
- On this Windows/Vite 8.3.2 build, all route-aware budgets pass: initial JavaScript 547,046 B / 169,798 B gzip; initial CSS 74,209 B / 13,711 B gzip; the largest incremental lazy route is `model-page` at 444,523 B / 129,636 B gzip; the largest full route is 991,569 B / 299,434 B gzip. The limits include modest headroom and will need exact-SHA Linux CI confirmation before treating these as a stable cross-runner baseline.
- The historical M0.03 sample records a 434.89 kB main chunk and 64.47 kB CSS. The apparent main-chunk change is small and CSS tooling/source configuration differ; no same-environment archived build artifact or exact compression report is available for a controlled comparison. It is therefore not evidence of a material measured improvement.
- `pnpm ui:budget` passed for the reusable UI catalog at 410,816 B JavaScript / 123,279 B gzip and 42,863 B CSS / 9,104 B gzip, under its explicit catalog-specific budgets. This budget does not cover the Board application bundle.

## Review decision and follow-up

- Keep the separated ORM, client, UI and asset package boundaries: the workspace graph shows multiple real consumers and no runtime/package cycles.
- Do not split large generic API or Board views by line count alone. Prioritize behavior-preserving extractions with focused endpoint/browser assertions; the current generic API route and list view remain large responsibilities documented in [refactor-map](../../engineering/refactor-map.md).
- Keep the Board budget separate from the UI catalog budget; both are now independently enforced. Review budget changes deliberately when route structure or the build toolchain changes.
- Re-run this review on Linux CI with the same lockfile/toolchain and retain machine-readable raw/gzip results before closing M9.08. Current workflow hosted checks on recent source are not verified in this session because GitHub CLI authentication is invalid and anonymous API access is rate-limited.
