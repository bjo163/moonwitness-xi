## Contract decisions

- Task identity is repository ID plus stable Task ID, never an issue number or mutable title.
- Roadmap source owns scope, dependencies, acceptance, milestone and managed labels. GitHub owns assignee, discussion and maintainer triage. Verified Git/GitHub metadata owns source, CI, promotion and release evidence.
- Human notes remain outside the managed body markers. Marker corruption, duplicates, or orphan issues require triage and never cause automatic deletion.
- Manual close cannot update the roadmap checkbox. Incomplete acceptance yields `needs-triage`; the bot does not auto-reopen/close-loop.
- Implementation lifecycle (`planned`, `in-progress`, `blocked`, `verified-dev`) is separate from delivery (`in-main`, `released`). A verified stage must name evidence for the same current SHA.
- Issue text and events are untrusted proposals; no arbitrary shell, git, release or URL-fetch behavior is allowed from issue content.
