## Contract implemented

- Every planned update records the expected title, managed block, and milestone. Immediately before PATCH, the executor fetches that issue again.
- Changes to title, milestone, or generated block since planning fail closed unless the issue already reached the desired value. Malformed/duplicate boundaries also fail before write.
- A concurrent edit to text outside the generated block is preserved by merging the desired managed block into the latest body. Latest human labels and assignees are carried into the update.
- If another synchronizer already wrote the desired state, the executor skips PATCH. There is no retry loop and no timestamp-driven churn.
- The GitHub adapter exposes a single-issue read operation; update execution requires that capability.
