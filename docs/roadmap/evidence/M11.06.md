## Implemented

- `.github/workflows/roadmap-issue-plan.yml` is now the single Roadmap issue sync workflow. It performs bounded apply for changed roadmap tasks pushed to `dev`, daily backfill when the workflow is available on default `main`, and explicit manual runs on `main` or `dev`.
- Push `dev` compares the prior and current roadmap checklist, task index, task-card sections, and evidence, then applies only changed Task IDs. Automatic and manual apply are limited to five tasks per run; manual apply requires the explicit boolean `apply` and comma-separated Task IDs.
- The daily `schedule` now plans against the latest `origin/dev` SHA even though GitHub starts scheduled workflows on default `main`. It picks at most five create/update operations from the full plan, re-checks that `dev` has not moved before writing, and shares the repository writer coordinator. Manual dispatch also has an explicit `backfill_next_batch` option.
- The plan job receives `issues: read`. Only the conditional apply job receives `issues: write`; it follows the plan job, checks out the exact dispatch SHA with persisted Git credentials disabled, and serializes on the repository write coordinator.
- `selectTasksForSync` rejects unknown IDs, duplicates, malformed/empty entries, missing selection for apply, and apply batches larger than five. Retrying a partially completed task selection recomputes remote state, so already-synced issues become no-ops before remaining operations continue.
- `changed-task-ids.mjs` selects task-level changes for checklist, index, shared card sections, and evidence. Unrelated changes select nothing; deleting a roadmap task fails closed rather than closing/deleting its issue.
- Plan logs expose source SHA, remote-input fingerprint, and operation counts/task IDs, but omit issue body text and maintainer notes. API reads honor bounded `Retry-After`/rate-reset/transient retries; writes stay serial and are not blindly retried.
- `--help` documents the safe CLI selection contract. Existing root planner command remains read-only unless explicit apply flags are used.
