# Evidence M11.06 — Scheduled read-only issue reconciliation

## Status

- Status: read-only planner workflow and bounded API read retries are implemented; remote hosted activation and any write batching remain pending.
- Source branch: `dev`.
- Implementation follows M11.03–M11.05 contracts and does not create or update GitHub issues.
- The workflow is scheduled weekly, runs for relevant pushes to `dev`, and supports manual execution only on `dev` or `main`. Runs are serialized by ref and use the immutable event SHA.
- The weekly schedule starts after the workflow reaches the repository default branch; the push/manual paths are scoped to trusted `dev`/`main` refs.

## Delivered

- `.github/workflows/roadmap-issue-plan.yml` requests only `contents: read` and `issues: read`, uploads a source-SHA-named plan artifact for seven days, and has no `--apply` path.
- The CLI can write a JSON plan to a repository-relative file while reporting only operation counts in quiet mode; generated local output is ignored by Git.
- GitHub read requests retry up to three times for transient failures and rate limiting. `Retry-After` and primary rate-limit reset timestamps are honored only within the configured wait bound. A permission-denied 403 remains an immediate error.
- POST/PATCH writes are never retried by the generic API layer, avoiding blind duplicate mutations; ambiguous issue creation retains its explicit marker re-read recovery.
