## Implemented

- Added a closed JSON Schema envelope with a version marker, at most 20 suggestions, and exactly three kinds: summary, term, and duplicate. Unknown properties are rejected.
- Every candidate is constrained to `unreviewed` and `INTERNAL`, with canonical suggestion, Assertion, and Evidence identifiers and bounded citation metadata.
- Citations bind exact source/edition/locator, full-source SHA-256, Unicode-scalar range, and selected-span SHA-256. The trusted resolver rechecks source identity, digest, readability, and selected-span digest.
- Summary text must exactly equal its cited spans in order; term text must exactly equal its one cited span. Duplicate suggestions require two distinct active/readable Assertions and readable active Evidence bound to each requested Assertion. The schema includes no rationale or merge instruction fields.
- `validateResearchSuggestionEnvelopeWithResolver` fails closed on malformed envelopes, unavailable or mismatched sources, invalid spans, unsupported text, unreadable/inactive records, and invalid Evidence-to-Assertion bindings. It performs validation only and has no canonical write path.
- The async validator snapshots JSON input before resolver awaits, gives the resolver detached selectors, and returns only the validated snapshot. The ORM store persists that return value rather than rereading caller-mutable input.
- Store and read services snapshot authenticated user, company, role, identifier, and requested version fields before asynchronous validation or transaction work.
- Added immutable PostgreSQL suggestion versions scoped by active user, company, and membership. Each complete suggestion is stored as hidden canonical JSON with its digest, version, `INTERNAL` visibility, and `unreviewed` state. Exact retries are idempotent; changed content appends a new version; company-row locking serializes version allocation.
- Reads remain company-scoped, verify active membership, the stored digest, canonical JSON shape, and `INTERNAL`/`unreviewed` status. Append-only triggers reject SQL `UPDATE` and `DELETE`. The store has no path to canonical graph writes.
- Tests byte-check the two approved local sample artifacts and exercise malformed shapes, citation/span mismatch, unsupported text, duplicate binding, resolver-await caller mutation, tenant access, idempotency, append-only rules, and tamper detection.
