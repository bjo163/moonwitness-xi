## Coverage and findings

- E2E creates a regular user and company-scoped partner fixture, signs in as that user, edits the linked profile, reloads the stored partner values, and confirms only the authenticated user's partner is targeted.
- The profile query now fetches the current server user through `/auth/me` before resolving `partner_id`; it returns `null` while the user has no linked partner instead of returning `undefined` from a React Query function.
- Language and timezone preferences are saved through the authenticated endpoint and remain after reload. The seed currently exposes English (US) only; the test verifies its persisted selection and changes timezone to `Asia/Jakarta`.
- Wrong current password is rejected with HTTP 400. A mismatched confirmation stays in Settings without changing the password. A valid change returns HTTP 200, logs out, rejects the old password, and accepts the new password.
- E2E-only API rate limit is raised to prevent the isolated auth scenarios from consuming the application's normal 10 requests/minute allowance. Runtime API rate limits are unchanged.
