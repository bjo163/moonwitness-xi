# Evidence M9.02 — Typed attachment storage and reconciliation

## Status

- Implemented on `dev` with a typed storage provider boundary and a compatible local-filesystem provider. Hosted CI evidence will be added after the source commit is pushed.
- Existing attachment metadata, IDs, ownership links, UUID storage keys and direct `ATTACHMENT_STORAGE_DIR/<uuid>` object layout remain unchanged. Existing bytes remain downloadable after API injection changed to the provider.
- No cloud provider is claimed or configured. No public object URL or credential path was introduced.

## Delivered behavior

- `@moonwitness/orm-storage` provides a manifest, `AttachmentStorage` contract and `LocalFileAttachmentStorage` with UUID-only keys, atomic temp-file writes, safe reads, idempotent deletes and object checksums.
- API upload/download/hard-delete routes use the provider while authorization remains in the API: parent record/company scope, 10 MiB limit, MIME/name validation, checksum, private forced-download headers and transactional metadata/audit/outbox behavior.
- The legacy `attachmentStorageDirectory` app option remains supported; a new typed `attachmentStorage` injection seam enables provider tests/adapters without changing persisted attachment records.
- `pnpm attachments:reconcile` reports missing/corrupt references and old unreferenced local UUID objects. It is dry-run by default. `--apply` requires an explicit `--older-than` cutoff and supports a bounded `--limit` from 1 to 10,000; non-UUID/temp files and fresh objects are ignored.
- README, generated package/API/model docs, architecture diagrams, `.env.example`, feature matrix and operator contract were updated. No `any` types were added.

## Limits and operations

- Local filesystem storage still requires persistent shared storage between API instances serving the same database. Cloud/object storage, malware scanning, content sniffing and automated expiry policy remain unsupported.
- Reconciliation snapshots current DB references, reports checksum/size mismatches, and is dry-run by default. Deletion is an explicit operator action and only considers stale UUID-named files in bounded batches. Review output and take a backup before `--apply`.
- Archived attachment bytes do not expire automatically. Retention duration is a product/operator policy and must be decided before automatic archive expiry is enabled.
- No application deployment was performed.
