## Implemented

- Added `findDuplicateCandidates` to `@moonwitness/research`. It compares validated assertions using normalized claim features, polarity, scope, context attribution, lifecycle/review eligibility, epistemic/review state, and readable evidence selectors.
- Every candidate has `status: unresolved` and a rationale. Candidate generation cannot merge, update, or assign a canonical identity. It reports bounded features, not semantic certainty.
- The scorer strictly validates visibility and omits hidden records and evidence linked to unreadable assertions. The API raises generic storage `PUBLIC` to an effective `INTERNAL` floor and admits only effective `INTERNAL` records. It returns opaque record/evidence IDs, rationale and counts; claim text and excerpts are not returned.
- Added authenticated `GET /api/research/duplicate-candidates`. `system` service callers can use it directly; human `user` and `superadmin` callers require the active company context derived by the auth plugin. Responses are `private, no-store`. The route uses only the active `research` release from PostgreSQL, which is digest-verified and ontology-validated inside a short transaction. It performs no network lookup and accepts no arbitrary graph/corpus input.
- The active `research` release is currently a shared corpus. A human caller's company context authenticates eligibility; it does not partition records in that release. Keep tenant-specific/private records out of the shared release; only the approved synthetic pilot and independently approved shared source material are in scope until release records and queries support company scope.
- Added canonical release ceilings in `@moonwitness/orm-knowledge`: 5,000 rows and 8 MiB combined for the canonical manifest and record JSON. Creation rejects oversized data. Reads check manifest/count first, then aggregate bytes from a SQL subquery capped at 5,001 rows; oversized/stale releases fail closed before content materialization. The route passes a 100-pair scorer limit and caps output at 100 candidates and 500 evidence IDs, marking truncation.
- Tests include scorer and API privacy/determinism cases, authenticated-role enforcement, generic malformed/unavailable responses, output cap behavior, OpenAPI contract, and an isolated PostgreSQL API integration fixture with matching internal assertions plus a restricted assertion. The integration checks exact active release digest, unresolved result, anonymous denial and absence of restricted ID/claim text.
- No legacy repository records, external runtime source, or cross-work textual claim are used. Fixtures are synthetic; the route does not establish a real duplicate or G3 research fact.
