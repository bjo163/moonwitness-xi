# Evidence M3.09 — Board resilience and query isolation

## Status

- Status: implementation and local acceptance complete on `dev`; GitHub CI/promotion validation follows the pushed source commit.
- Date: 2026-10-04.
- Executor: Codex.
- Prerequisite: M3.01 Playwright harness with an isolated PostgreSQL E2E database.

## Contract and result

- Added a shared query-key scope containing the authenticated user ID and selected company ID. Model metadata, views, list/detail reads, dashboard data, activity counts, tags, fields, chatter, and scheduler queries now use this scope.
- Previous list data may only be used as placeholder data when the prior key belongs to the current user/company and the same model. This prevents stale rows from appearing while another scope loads.
- A principal change clears the React Query cache. Company changes remount the current route and use a new scoped key; old-scope queries are not invalidated/refetched using the new tenant header.
- List network failures now have an accessible alert and retry action, with a retrying state. Record save has a synchronous guard against repeated submissions before React renders the pending state.
- Added browser coverage for loading, an offline failure, recovery/retry preserving the search, the empty state, exactly one POST on repeated save clicks, account switching, and company switching. The account-switch assertion confirms no previous-account row remains; user partner visibility remains governed by the existing owner record rule.
- Company membership creation by system/superadmin can target another company, while the ordinary company-owned record checks remain bound to the active company. This enables administrator membership management without allowing a normal user to cross the tenant boundary.
