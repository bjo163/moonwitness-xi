## Behavior

- Replaces repeated `gh issue comment` calls with an idempotent issue upsert using GitHub REST. Five repeated failures reuse one open `docs-publication` issue and append distinct workflow links to its managed block; history is capped at ten unique runs.
- Human-authored title, labels, and body outside the managed block are preserved. Duplicate issues and malformed managed delimiters fail closed before an issue write.
- A successful trusted Pages deployment updates and closes only the open issue carrying the exact `docs-publication` label. It keeps failure history and records the successful run. It never searches for, edits, comments on, or closes security reports.
- Both reporter jobs serialize on the repository write coordinator. Failure and recovery handlers require a verified build source SHA; a dispatch rejected by the trusted-ref policy cannot create an incident issue.
- A shared `maintenance-incident.mjs` reconciler applies fixed category configuration for `docs-publication` and `platform-audit`. Each category uses its own label and managed body markers, so recovery cannot close another category's issue. Platform audit recovery runs only after the complete audit job, including baseline artifact upload, succeeds on `main`.
- Reporter uses only `issues: write`; no workflow token or response payload is printed.
