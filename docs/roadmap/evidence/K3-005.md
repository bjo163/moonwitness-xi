# Evidence K3-005 — research review decision event contract

## Status

- Status: in progress; a generic workflow event can now persist a hidden canonical JSON payload atomically, but the authenticated research adapter and authoritative record bindings remain unimplemented.
- Date: 2026-10-16 (Asia/Jakarta).
- Dependencies: K3-001 scoped assertions and K3-004 reviewed relation graph projection.
- Scope implemented locally: versioned review-event schema and typed append-only reducer in `@moonwitness/research`, plus optional atomic payload persistence in `@moonwitness/orm-workflow`.

## Implemented

- Added `ontology/core/research-review-event.schema.json` and the typed `ResearchReviewEvent` contract.
- Events bind an assertion or relation content revision to a workflow instance, workflow event sequence/revision, outcome, reviewer, requester, evidence, visibility, idempotency key, and timestamp.
- The reducer rejects stale subject revisions, requester self-review, unsupported roles/outcomes, missing evidence, duplicate workflow actions, and idempotency-key conflicts. Exact retries return the existing event; distinct review decisions are appended without replacing history.
- Conflicting outcomes are retained and summarized as `conflicting`, scoped to one subject revision. Earlier revision decisions remain queryable after a subject revision changes.
- Review event visibility is promoted to the most restrictive visibility among the subject and its resolved evidence.
- `@moonwitness/orm-workflow` now supports a hidden nullable JSON payload on workflow event records. Canonical payload bytes are written in the same transition transaction and included in all idempotency replay comparisons. The addon moves from 1.0.0 to 1.1.0 through the ordinary additive model-sync path; a legacy-row test confirms the new field remains null for existing events. Start and timeout events continue to have no payload.
- Existing `@moonwitness/orm-workflow` also provides versioned definition snapshots, authenticated-role transition checks at its caller boundary, stale workflow revision rejection, requester/reviewer separation when configured, idempotent action replay, and transactional append-only workflow events.

## Remaining acceptance

- Implement a research adapter that validates the event against authoritative subject/evidence records inside the locked workflow transition and supplies the validated event payload. A generic JSON payload column alone does not verify research semantics or actor/requester/evidence bindings.
- Add and verify database-level protection against updating or deleting persisted review history; model access defaults alone do not establish database immutability.
- Wire authenticated actor and role from server-side authorization context; derive requester identity from the workflow instance and evidence visibility from authorized canonical records. Never accept those values from request payload.
- Add integration coverage for committed workflow transactions, duplicate/replay behavior at the adapter boundary, and authorized read projections.
- Do not add a graph/research database schema or API endpoint until the canonical snapshot/persistence decision and compatibility review satisfy ADR 0004.
