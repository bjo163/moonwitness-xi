## Implemented

- `ontology/core/research-review-event.schema.json` defines the versioned `ResearchReviewEvent` contract. Events bind the assertion/relation revision, active graph release digest, workflow instance/event sequence/revision, outcome, reviewer/requester, exact evidence IDs, visibility, idempotency key, and timestamp.
- `@moonwitness/orm-workflow` accepts an optional transaction-scoped payload preparation callback after locking the workflow and validating its transition. The prepared payload and workflow state/event are committed together. Exact idempotent replays compare the stable request intent and do not rerun the callback. Callback or event insertion failure rolls back the transition.
- `@moonwitness/orm-knowledge` stores immutable canonical PostgreSQL graph release manifests and records, an expected-head active-release pointer, append-only review event rows, and explicit append-only mappings from database users to canonical `mw:user:*` IDs. No SQL user ID is converted into an ontology identity automatically. Active-release reads also fail closed if a corrupted pointer resolves to a valid release for a different corpus.
- `transitionResearchReview` validates inside the locked workflow transaction that the workflow resource is a record in the active verified release and that the requested subject, revision, and evidence association match that release. It validates the full graph, verifies evidence selectors against pinned local corpus bytes, derives requester identity from the workflow starter, checks authenticated user role/company membership, and persists the event atomically with the workflow transition.
- Evidence visibility is floored at `INTERNAL` when generic storage says `PUBLIC`; a public storage flag cannot confer publication approval. Event visibility is at least as restrictive as the subject and all selected evidence.
- Only terminal approved/rejected transitions create a research decision projection. Intermediate workflow votes remain in the append-only workflow event log. The adapter is a package service only: no HTTP route or public CRUD exposure was added.
- SQLite tests cover assertion and relation decisions, release binding, canonical actor mappings, idempotent replay/conflict, stale subject revision, role mismatch, invalid resource/evidence, rollback, self-review rejection, append-only raw SQL protections, and fail-closed behavior after privileged event corruption. Fixtures are synthetic apart from reading the already-approved local Tanzil Q7:46 bytes to verify the exact selector/hash. Quran source identity is derived from the validated local source manifest and must match the selector.
- Isolated-schema PostgreSQL integration tests cover graph release create/read/activate/rollback and append-only graph release/record protections, plus the actual review adapter's commit/replay, injected persistence-failure rollback, and append-only review-event protection. They were skipped locally because `POSTGRES_TEST_URL` is not configured; hosted execution must be checked on the implementation's exact SHA.
