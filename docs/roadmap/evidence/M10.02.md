# M10.02 — Board visual audit

**Status: partial; acceptance remains open.** The committed screenshots are historical captures from before the final mobile-header change (`f158658`, 2026-10-06 10:12 +07:00). They are useful for documenting the earlier layout issue, but they do **not** show the current header and must not be treated as visual evidence for the latest source. In particular, `M10.02-dashboard-mobile.png` still shows the old theme button and the two bell-shaped controls; the current source uses a calendar icon for pending activities, a bell for notifications, and moves the mobile theme action into the user menu. Full browser E2E acceptance remains open because persisted user outcomes and the PostgreSQL browser flow have not been exercised against the latest source.

## Environment and coverage

- Served the actual Vite Board and API from the current checkout, using the normal addon seed path against an isolated in-memory SQLite database. No user database or production service was accessed.
- Authenticated as the locally seeded `superadmin` account with a throwaway audit-only password.
- Inspected login and authenticated dashboard, profile, settings, and partner directory at 1440px desktop width; inspected dashboard, profile, and partner directory at 375px mobile width.
- Checked document width against viewport width and inspected browser page errors/console output.

## Results

- All audited routes rendered meaningful content. No browser page errors or application runtime errors were reported; the only console info was Vite connection and React DevTools guidance.
- No horizontal document overflow was observed at 1440px or 375px on audited routes.
- Desktop profile/settings controls and seeded directory records are present. Seed coverage visibly includes 10 partners and 2 users.
- The mobile dashboard hero title initially collided on its wrapped line. The Board heading now uses mobile-specific sizing/leading and the hero uses tighter small-screen padding; a fresh 375px browser capture confirms the title no longer overlaps and the document remains within the viewport.
- Follow-up header review found unlabeled company/user controls, two indistinguishable bell icons, and a theme button crowding the 375px header. Commit `f158658` adds accessible labels, distinguishes the activity icon, and moves the mobile theme action into the user menu. Board typecheck, lint, format check, and production build pass at that commit. Source inspection confirms the activities button is labelled “Pending activities” and uses `CalendarClock`, while the notification control is labelled “Notifications” and uses `Bell`.
- Added Playwright assertions for these mobile controls and for toggling/restoring the theme through the user menu. These assertions have **not** run against `f158658`: Docker is unavailable and `127.0.0.1:55432` has no PostgreSQL listener, so the required isolated Postgres browser fixture could not start. The earlier dashboard axe-core run reported zero violations, but that result predates the current header and the full route/browser matrix remains pending.
- The committed PNGs were captured before `f158658`; keep them as historical context only. Regenerate and review the complete screenshot set after the PostgreSQL-backed browser matrix passes, then replace the stale evidence in the same milestone update.
