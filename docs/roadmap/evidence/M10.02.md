# M10.02 — Board visual audit

**Status: partial; local Chromium/Firefox/WebKit visual acceptance is verified, while PostgreSQL-backed browser and persisted-mutation acceptance remains open.** Fresh screenshots below were captured on 2026-10-06 from the current Board source after the mobile-header change (`f158658`). The current header uses a calendar icon for pending activities, a bell for notifications, and moves the mobile theme action into the user menu.

## Environment and coverage

- Source SHA: `7658dc31f4b74be491cf1c8b240e89068a26aa7d` (three-engine visual matrix and reusable runner).
- Reproduction command: `pnpm test:e2e:visual:matrix`. It serves the actual Vite Board and API from the current checkout using the normal addon seed path against an isolated in-memory SQLite database. No PostgreSQL service, user database, or production service is accessed. This quick visual runner is separate from the standard PostgreSQL E2E gate.
- Authenticated as the locally seeded `superadmin` account with the E2E-only password.
- Ran `apps/board/e2e/visual-audit.spec.ts` on Chromium, Firefox, and WebKit on Windows: **6 tests passed (2 per engine)**. Login was exercised at 375px, 768px, and 1440px. Authenticated dashboard, partner list, partner form, profile, and settings were exercised at all three widths in both light and dark themes (30 route/viewport/theme combinations per engine; 90 total).
- Checked document width against viewport width in every authenticated combination. All 10 desktop route/theme axe-core checks passed with zero violations per engine (30 scans total). The audit also exercised keyboard navigation, opening/closing model navigation, the mobile header's accessible controls, and switching/restoring theme from the user menu.

## Results

- All audited routes rendered meaningful content in each browser engine.
- No horizontal document overflow was observed at 375px, 768px, or 1440px on audited routes.
- Desktop profile/settings controls and seeded directory records are present. Seed coverage visibly includes 10 partners and 2 users.
- The mobile dashboard hero title initially collided on its wrapped line. The Board heading now uses mobile-specific sizing/leading and the hero uses tighter small-screen padding; the current 375px capture confirms the title no longer overlaps and the document remains within the viewport.
- Follow-up header review found unlabeled company/user controls, two indistinguishable bell icons, and a theme button crowding the 375px header. Commit `f158658` adds accessible labels, distinguishes the activity icon, and moves the mobile theme action into the user menu. Current-source screenshots and Playwright assertions verify these controls; the activities button is labelled “Pending activities” and uses `CalendarClock`, while notifications is labelled “Notifications” and uses `Bell`.
- The first browser run exposed two fragile partner-row locators because partner name and country are each rendered twice in the same row. The assertions now select an exact-text match. It also exposed a real responsive test defect: the theme matrix tried to use the desktop theme button at mobile width, where the button is intentionally hidden. The matrix now switches themes through the user menu on mobile. The complete local visual suite passes after these fixes.
- The normal PostgreSQL browser fixture remains unrun: Docker is unavailable and `127.0.0.1:55432` has no PostgreSQL listener. Thus persisted mutation/readback, PostgreSQL behavior, and permission-negative browser paths remain pending. The local SQLite visual run does not replace those acceptance checks.
- The committed PNG set has been regenerated from Chromium and manually reviewed for the mobile header. It includes desktop/mobile dashboard, partner, profile, settings, and login captures; the full 99-capture three-engine run is retained in ignored `test-results/visual-audit/` for local inspection. Windows-specific Playwright baselines were added for the three Chromium visual regression assertions so checks run repeatably on this platform.
