# Evidence M7.06 — Curated changelog renderer

## Status

Implemented locally; hosted technical CI is pending for the implementation commit.

## Changes

- `pnpm release:changelog <plan.json> <YYYY-MM-DD>` renders a release section to stdout only, with version/date and source/baseline SHA metadata.
- Renders Added, Fixed, Performance, Security, Breaking Changes, and Upgrade Notes from the plan's classified source commits.
- Links every entry to its source commit. Adds a PR link only when the Conventional Commit subject has a trailing `(#number)` marker.
- Requires a non-empty `UPGRADE:` trailer on every breaking commit; missing instructions fail closed.
- Security commit subjects and bodies are not copied verbatim; public notes use a generic security summary. Other bodies are omitted except the dedicated upgrade trailer.
- Does not mutate `CHANGELOG.md`, tags, package versions, GitHub Releases, images, or Pages; the generated output is reviewable before release preparation.

## Verification

- `pnpm test:render-changelog` — passed (5 tests): sections/source links/PR links, breaking upgrade required and rendered, invalid plans and repository URLs rejected, date/category validation, and security detail redaction.
- `pnpm test:release-plan` — passed (4 tests); release plan now carries classified commit metadata used by this renderer.
- End-to-end CLI dry-run using a temporary plan file — rendered the candidate `v1.1.0-rc.1` section and commit links from actual local history; temporary output removed afterward.
- `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, and `pnpm docs:check` — passed.
- `pnpm exec actionlint .github/workflows/ci.yml` — passed; the new suite is part of hosted automation tests.
- Hosted technical CI result will be recorded for the implementation SHA.

## Limits

- This renders a candidate section only. It does not generate/overwrite the complete historical changelog, create release notes remotely, or authorize a stable release.
