# Evidence M2.09

- Status: workflow policy implemented. The dev CI cancellation behavior is verified; non-canceling release verification still needs a two-dispatch check.
- CI concurrency is keyed by PR base branch or push branch name. Updates on `dev` cancel stale `dev` verification, while a full `dev → main` PR uses a separate `main` group and is not canceled by a later dev push.
- Promotion has a single non-canceling concurrency group. Before creating/updating the PR, it compares the event SHA with `git ls-remote origin refs/heads/dev`; stale events exit without writing, leaving the newer push run to handle promotion.
- Release runs use a non-canceling group keyed by `github.ref`, so retries for the same tag do not terminate an active verify/publish run. Different release tags remain independent because they publish distinct immutable version tags; the mutable `latest` alias race remains tracked for release hardening.
