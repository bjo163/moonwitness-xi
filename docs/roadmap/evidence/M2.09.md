# Evidence M2.09

- Status: complete for CI cancellation and same-ref release serialization.
- CI concurrency is keyed by PR base branch or push branch name. Updates on `dev` cancel stale `dev` verification, while a full `dev → main` PR uses a separate `main` group and is not canceled by a later dev push.
- Promotion has a single non-canceling concurrency group. Before creating/updating the PR, it compares the event SHA with `git ls-remote origin refs/heads/dev`; stale events exit without writing, leaving the newer push run to handle promotion.
- Release runs use a non-canceling group keyed by `github.ref`, so retries for the same tag do not terminate an active verify/publish run. Different release tags remain independent because they publish distinct immutable version tags; the mutable `latest` alias race remains tracked for release hardening.
- Explicit timeouts: planner 10m, quality 30m, automation 15m, integration 45m, browser 30m, container 30m, gate 15m, promotion 15m, release verify 60m and publish 30m.
- Local verification: actionlint and lint passed; both `pnpm test:ci-gate` (10 cases) and `pnpm test:affected` (3 cases) passed.
- Remote CI race check: push `f7f230c` was superseded by `b31c7b2`; run [37171696638](https://github.com/bjo163/moonwitness-xi/actions/runs/37171696638) canceled its stale required jobs, and `ci-gate` rejected that incomplete run. The newer docs-only run [37171714924](https://github.com/bjo163/moonwitness-xi/actions/runs/37171714924) ran only quality + automation and passed its gate. This proves stale CI cancellation does not create a false-green gate.
- Remote release race check: two non-publishing release verification dispatches for the same `dev` ref, version `1.0.0-rc.1`, were started concurrently. [37172005570](https://github.com/bjo163/moonwitness-xi/actions/runs/37172005570) completed successfully with `publish` skipped; [37172007276](https://github.com/bjo163/moonwitness-xi/actions/runs/37172007276) remained pending until the first finished, then also completed successfully with `publish` skipped. This confirms same-ref release verification is serialized without canceling an active run.
- Limitation: distinct semantic versions may run concurrently. They publish immutable version tags but currently also update mutable `latest`; that alias race remains open in release hardening (M7.08).
