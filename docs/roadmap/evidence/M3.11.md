## Coverage and implementation

- Per-change Board CI remains Chromium-only to keep routine feedback lean.
- Added `.github/workflows/browser-matrix.yml`, scheduled weekly on Monday at 03:37 UTC and manually dispatchable. It fans the complete Playwright E2E suite into independent Chromium, Firefox and WebKit jobs; each uses isolated PostgreSQL, installs only its own engine, scans text reports before artifact upload and retains sanitized JUnit/retry diagnostics and screenshots for seven days.
- `MW_E2E_BROWSER_MATRIX=true` adds Firefox and WebKit projects; normal local/CI runs remain Chromium-only unless the matrix is explicitly enabled.
- A cross-engine audit timing issue was found: Firefox could run axe while the login panel was still fading in, which caused false low-contrast findings on the entire form. The audit now waits for the animated heading and speech bubble to reach full opacity before measuring contrast.
- A WebKit edit-form run exposed a race between record hydration and input editing. The test now waits for the expected record value and enabled Save button before submitting the edit.
- Browser coverage is Playwright desktop-engine testing with emulated responsive viewports; it does not claim physical iOS/Android device coverage.
