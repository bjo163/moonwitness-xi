## Contract and result

`base.user` defines a password field that is write-only and hashed by the ORM password hook. Fresh install creates the system and superadmin accounts without a built-in password. API startup reads `SUPERADMIN_PASSWORD`, applies it only when the seeded superadmin password is still null, and enforces the supported length. Root `pnpm reset:superadmin-password` uses the same environment setting and performs an explicit reset without printing the password.

Regression coverage verifies missing initial password remains unset, configured initialization produces a salted verifiable hash, wrong passwords fail, system user stays unchanged, changed password survives addon reinstall and a later startup password, explicit reset invalidates the old password, invalid/missing-account reset fails, password hashes remain hidden, and the password field is added programmatically on upgrade. PostgreSQL API integration verifies the configured startup credential logs in and an explicit reset switches authentication to the reset credential.
