## Delivered behavior

- Added `pnpm test:addon-conformance`, wired into both `pnpm test:unit` and `pnpm test:unit:ci`.
- The suite covers all seven runtime addon manifests: `base`, `auth`, `jobs`, `notification`, `organization`, `orm-storage`, and `workflow`.
- It checks unique addon/model/seed identities, semantic versions, declared dependency closure, public root exports, package build/test scripts, view/menu consistency, and seed ownership/namespacing.
- It installs the complete addon set in reverse declaration order against an isolated SQLite database, checks required sample counts and seed external-ID coverage, then repeats installation to prove stable versions/identity/counts and preserves a maintainer edit.
- `orm-storage` is intentionally provider-only with no ORM models or demo records. Append-only audit events and other runtime events remain empty instead of receiving fabricated history.
- The conformance suite exposed that `base.audit_log` had a Development Mode menu without a declared view. Added a read-only view with event metadata in the list and change details in the form; existing admin-only access remains in force.
- Added a programmatic upgrade test proving an exact prior-version hook runs once and advances the installed addon version. Addon manifests that have no released prior schema version do not need empty upgrade hooks; explicit transformations remain programmatic, with no SQL migration layer.
- The UI package consumer fixture now installs peer dependencies offline from the workspace package cache, keeping the packed-package contract test deterministic and removing an unnecessary registry wait.
- Existing API negative-authorization suites cover tenant boundaries and denied operations for base/auth, jobs, notifications, workflow, and organization; storage is a provider package with no generic API model. API coverage was run with all five relevant endpoint suites.
- No explicit `any` was added.
