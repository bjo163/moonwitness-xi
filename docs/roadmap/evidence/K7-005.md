## Implemented locally

- Added a suggestion-only adapter for `summary`, `term`, and `duplicate` candidate generation. It accepts bounded passage fields, copies only the explicit source/evidence/assertion allowlist, and serializes passage text as JSON data after a fixed policy that labels it untrusted evidence.
- The runtime dependency is restricted to `Pick<LocalAiRuntime, 'generate'>`; the adapter has no persistence, execution, publishing, network, or credential-reading dependency. The existing runtime itself is disabled by default and only connects to a configured loopback endpoint.
- Provider output is treated as untrusted: strict JSON parsing happens before the injected validator runs. Invalid JSON, oversized output, provider failure, or validator failure returns no candidate. The adapter returns the validator's accepted value only; persistence remains a separate K7-004 operation.
- Context validation enforces non-empty identifiers, SHA-256 shape, passage count and text bounds, and a maximum prompt size. Extra input properties are discarded before prompt construction.
- Adversarial fixtures include attempts to override rules, execute shell commands, publish content, and reveal a credential marker. Tests confirm those strings remain JSON source data, extra properties do not enter the prompt, and no tool capability is present.
- Trusted validator and provider callbacks are captured before the provider await; a regression test mutates both caller-held properties while generation is pending and confirms only the captured callbacks run.
- API-package tests wire the adapter to `validateResearchSuggestionEnvelopeWithResolver`: unsupported injected output and an extra `execute_shell` property are rejected; an exact synthetic cited span is returned only as `unreviewed`/`INTERNAL` candidate data. The adapter is not given a persistence function.

## Remaining acceptance

- The model may still produce arbitrary text or ignore prompt instructions. The security guarantee is the tool/capability boundary plus trusted validation, not prompt wording alone. Any API route must construct passages from the K7-004 exact-source and active-tenant resolver, then use the resolver-backed validator before returning or storing candidates.
- The API-package tests exercise the adapter and validator together but do not test an HTTP authorization route, source allowlist, tenant isolation, or database persistence. Add those cases before exposing generation through an API. Do not expose generated text directly to users or promote it to canonical records.
- A fake provider validates the local boundary contract but does not establish model-specific resistance to prompt injection. Any model evaluation belongs to K7-006 and must use the named local model/device with source scope and limits documented.
- No hosted verification, release, promotion, or deployment is claimed by this local slice.
