## Delivered

- Added a strict docs-content classifier. Only `docs/**/*.md`, `README.md`, and `ROADMAP.md` count as docs-only; executable generators, Board/docs app code, package manifests, lockfiles, workflows, assets, generated JSON and mixed renames do not.
- Pages change detection records both docs-only status and Conventional Commit release change kind. A pure docs-only change must classify as `none` for application release planning.
- `build-info.json` records monorepo application version separately from immutable source SHA/ref and docs-only/release classification.
- Main publication waits for the latest `CI` push workflow run on `main` with the exact immutable source SHA, then verifies its `ci-gate` job. Branch names are resolved from the triggering event SHA to avoid publishing a later, unverified tip.
- Pages publish/retry remains isolated from release workflow; a docs failure issue links source and run without changing application version.

## Safety and handoff

- The docs-only classifier is intentionally conservative. A mixed docs+code change is treated as code and still depends on full main CI before publication.
- CI check polling is pinned to one source SHA; a failing, cancelled, absent, or stale check cannot authorize deployment.
- First main publish requires fresh CODEOWNER review through the existing promotion policy.
